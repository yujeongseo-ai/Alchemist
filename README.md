## 1. 공통 생성 조건

네 데이터셋은 동일한 PHANTOM 랩(KVM 기반, KENTECH CSS LAB)에서, 동일한 수집 원칙으로 만들어졌다. 차이는 어떤 공격 시나리오를 실행했는가뿐이다.

- **수집 방식:** 각 보안 장비에서 로그를 **직접** 읽었다(SIEM 사본 아님). 원본 값은 재작성하지 않았다.
- **수집 구간:** 시나리오 실행 **시작 직전 지점**부터 장비별로 읽은 뒤, **이벤트 타임스탬프 기준**으로 시나리오 시작~종료 구간만 남겼다. 배경 트래픽과 이전 실행분은 제외된다.
- **시간 동기화:** 실행 전 모든 VM 시계를 UTC로 맞춰, 소스마다 다른 시간대(일부 +0900) 로그도 같은 기준으로 정렬·절단된다.
- **Zeek 체크섬 보정:** NIC 오프로드로 Zeek가 페이로드를 버리던 문제를 `ignore_checksums`로 보정한 뒤 수집했다. 그 결과 Zeek의 http·files·ssh가 정상 기록된다.
- **WireGuard 제외:** OCSF 매핑 클래스가 없는 소스(ocsf\_mapping.csv 기준)라 데이터셋에서 제외했다. VPN 활동은 시나리오 실행 로그(ground truth)에만 남는다.
- **CrowdStrike Falcon:** 클라우드 등록 시각이 아니라 실제 **탐지(event) 시각** 기준으로 구간만 포함했다.
- **실행 로그(ground truth):** 공격자 VM의 시나리오 실행 로그는 "정답" 기록으로, 각 폴더에 별도 보관한다.

## 3. 시나리오별 설명

### 시나리오 1 — 웹 애플리케이션 침해에서 다채널 유출까지

DMZ 웹 서버를 겨눈 **웹 APT 체인**이다. 정찰 → SQL 인젝션 → 웹셸 업로드·RCE → DB 서버로 횡적 이동 → C2 비콘 → 다채널 유출(cloud/SCP/SSL/SMTP)까지 8단계로 실행하고, 마지막에 Falcon EDR 부하를 생성한다. 공격자는 WAF(10.10.10.40)를 거쳐 웹 서버(10.10.10.20)에 접근하므로 웹 로그의 출발지가 WAF IP로 남는다. 웹 트래픽이 많아 **Suricata·WAF·Zeek·Falcon(11건)** 에 탐지가 집중된다. 반면 SSH 브루트포스·호스트 침입 규칙은 유발하지 않아 Wazuh·Fail2ban은 0건이다. 데이터셋 크기가 가장 크다(약 76 MB).

### 시나리오 2 — 스피어 피싱에서 Windows 엔드포인트 침해까지

가짜 VPN 포털 피싱으로 시작해, 수집한 계정으로 **Windows 클라이언트(SEC-CLIENT-01)에 WinRM/NTLM으로 접근**하는 엔드포인트 체인이다. 자격증명 접근(LSASS·SAM), 지속성(예약 작업), 탐색, 횡적 이동, Decoy SMB 수집(47 MB/126파일), 아카이브 유출까지 9단계로 실행한다. 가짜 포털은 공격자 VM에 있고 실제 행위는 내부 클라이언트에서 일어나므로 **네트워크 흔적이 작다** — 연결 흔적은 방화벽 커널 로그(2,908건)에 가장 많다. 주의: **클라이언트 측 엔드포인트 텔레메트리(Falcon·Wazuh)는 이 데이터셋에 수집되지 않았다**. EDR 유발 행위는 실행 로그(ground truth)에만 남는다. 데이터셋이 가장 작다(약 810 KB).

### 시나리오 3 — 인프라 어플라이언스 텔레메트리

웹·엔드포인트가 아니라 **방어 어플라이언스 자체를 자극**하는 체인이다. Fail2ban(두 jail), Wazuh HIDS, WireGuard VPN 3대를 대상으로 SSH 자격증명 스프레이와 피어 핸드셰이크를 실행한다(5단계). 따라서 다른 시나리오와 달리 **Wazuh(62건)·Fail2ban(12건)에서 가장 많은 탐지**가 나온다. 대표 Wazuh 규칙은 5710(없는 계정 로그인 시도), 40112(연속 실패 후 성공), 5712·5551(브루트포스, 레벨 10) 등이다. WireGuard 핸드셰이크 3회는 OCSF 제외 소스라 실행 로그에만 남는다.

### 통합 — Full Chain 7-Phase 엔드투엔드 캠페인

시나리오 1\~3의 공격·방어 요소를 **하나의 캠페인으로 묶은** 데이터셋이다. 정찰 → 소셜 엔지니어링 → 초기 접근 → 웹 공격 → 횡적 이동·수집 → 지속성·방어 회피 → 유출의 7 Phase / 17 Step으로 실행한다. 웹 공격(Suricata·WAF·Zeek), 방어 어플라이언스(Wazuh 158·Fail2ban 9), 엔드포인트(Falcon 9건) 탐지가 한 데이터셋에 **모두** 나타나며, Falcon에는 **Windows 클라이언트 탐지(MaliciousPowershell) 1건**이 포함된다. 세 시나리오의 탐지 특성을 한 번에 보여주는 종합 데이터셋이다.

## 4. 활용 참고

- 각 데이터셋은 **이기종 보안 로그 → OCSF 정규화** 실험의 입력으로 설계됐다. 소스마다 형식(JSON·combined log·audit·kernel·eve.json)과 스키마가 달라, 정규화 난이도가 다양하게 분포한다.
- 시나리오 1·2·3은 **단일 공격 유형**에 집중한 데이터셋이고, 통합은 **다중 유형이 섞인** 데이터셋이다. 소스별 균형이나 특정 센서 중심 분석에 따라 골라 쓰면 된다.
- 소스별 줄 수가 0인 항목(예: 시나리오 1의 Wazuh, 시나리오 2의 Falcon)은 수집 누락이 아니라 **해당 시나리오가 그 센서를 유발하지 않은** 결과다. 각 폴더의 개별 문서에 사유가 정리되어 있다.
